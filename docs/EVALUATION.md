# Evaluation

## Data and split policy

The checked-in benchmark uses images generated by `examples/synthetic.py`; all source and expected readings are controlled by the renderer. Generated fixtures are licensed CC0-1.0. The generator creates one gauge per image, a fixed linear scale, random readings, small center/radius changes, and four conditions: clear, localized glare, blur, and additive pixel noise.

The benchmark command supports deterministic `train`, `validation`, and `test` seed ranges. It does not train a model. Policy calibration reads only a validation output and writes `backend/agents/policy.json`; the test seed range is separate and is not read by the calibration script. No SyncG images, labels, or real gauge photographs were used. This is a controlled software check, not a representative field benchmark.

## Compared methods

- **Baseline A — geometric only:** dial localization plus the radial Hough-line estimate. It emits a prediction whenever that estimator returns one; it does not apply image-quality abstention.
- **Baseline B — fixed two-estimator mean:** arithmetic mean of the geometric and polar readings whenever both return a candidate. It does not apply the quality gate or agreement policy.
- **Qyvoriq C — selective agent:** image-quality gate, supported geometry check, two estimators, validation-derived disagreement limit, one CLAHE refinement when needed, calibration-range check, and abstention/reinspection/human-review states. A reading enters its error summary only when its result state is `VERIFIED`.

The three methods run against the same generated image and calibration. Baseline latency includes localization and the estimator(s); Qyvoriq latency includes its quality and decision loop. It excludes upload/network latency. Runtime is serial on this x86-64 executor and should not be compared to AWS or COOL performance.

## Metrics

- Absolute error is divided by full-scale span and expressed as `%FS`; it is not divided by the observed reading.
- MAE, median, P95, and accuracy within 1%, 2%, and 5% FS use each method's predicted samples.
- Coverage is predicted/accepted samples divided by all benchmark samples.
- False acceptance is an accepted reading with absolute error greater than 5% FS, divided by accepted readings.
- The selective-risk curve applies quality and calibration-range gates, then varies only the raw two-estimator disagreement cap.
- Condition summaries report sample count, verified count, abstention rate, and selective error where accepted.
- Latency is measured with `time.perf_counter`; throughput is the reciprocal of mean per-image time for this serial run.

## Validation-derived policy

The disagreement cap is the 95th-percentile (`higher` quantile) raw estimator disagreement among quality-usable, in-range validation pairs whose fixed-mean error is at most 2% FS. It is fitted by `benchmarks/calibrate_policy.py`. A minimum of 20 eligible pairs is required. The saved artifact includes the source file, sample counts, fit method, and caveat. Quality thresholds themselves remain heuristic and are not statistically calibrated.

## Recorded results

The artifacts are machine-readable and produced by actual runs:

- `benchmarks/results/validation.json` — 120 validation-seed images used for policy fitting.
- `benchmarks/results/policy-calibration.json` and `backend/agents/policy.json` — policy fit provenance.
- `benchmarks/results/latest.json` — 120 test-seed images, evaluated after fitting.

The values below are from the checked-in `latest.json`. Percentages are synthetic-set statistics, not real-world accuracy estimates.

| Method | Predicted/accepted | Coverage | MAE (%FS) | P95 absolute error (%FS) | False accept >5%FS |
| --- | ---: | ---: | ---: | ---: | ---: |
| Baseline A — geometric | 109/120 | 90.83% | 0.5849 | 0.7683 | 0% (0/109) |
| Baseline B — fixed mean | 109/120 | 90.83% | 0.2863 | 0.4619 | 0% (0/109) |
| Qyvoriq C — selective | 59/120 | 49.17% | 0.2793 | 0.4161 | 0% (0/59) |

The test set contains 30 images per condition. Qyvoriq verified all 30 clear images, none of the 30 glare or 30 blur images, and 29 of 30 noisy images; the remaining image requested reinspection. It made no false accepts above 5% FS on this controlled test set. The refreshed run's mean per-image latency was 87.875 ms on this shared x86-64 executor, compared with 44.158 ms for geometric-only and 45.925 ms for fixed-mean fusion. Resources were not isolated, so these are run observations rather than deployment performance guarantees. The selective policy accepted fewer images while recording similar synthetic error to fixed fusion; this tradeoff is not evidence of real-world safety or accuracy.

The JSON also reports a 95% Wilson interval for the observed false-accept proportion under a simple binomial model. With 0/59 errors above 5% FS, its upper endpoint is approximately 6.11%, illustrating the limited evidence in a small accepted set. This model-based interval applies to the generated sample assumptions; it is not a bound on field risk.

## Reproduce

```bash
PYTHONPATH=. .venv/bin/python -m benchmarks.run_benchmark --split validation --samples 120 --output benchmarks/results/validation.json
PYTHONPATH=. .venv/bin/python -m benchmarks.calibrate_policy --input benchmarks/results/validation.json
PYTHONPATH=. .venv/bin/python -m benchmarks.run_benchmark --split test --samples 120 --output benchmarks/results/latest.json
PYTHONPATH=. .venv/bin/python -m benchmarks.run_reinspection --samples 30
```

`GET /api/benchmarks` exposes the latest JSON and the paired-observation result, and the Evaluation tab renders those actual values with synthetic-only labels.

## Controlled follow-up test

`benchmarks/results/reinspection.json` records a separate actual run of 30 paired observations. Each pair has an identical generated dial, geometry and stable reading, once with rendered glare and once without it. The seeds start at 42026 and are separate from the single-image validation/test ranges. All 30 glare inputs requested another observation and skipped both estimators; all 30 clear follow-ups were verified within 2% FS. All 30 persistent-glare cases escalated at the bounded retry limit.

This tests recovery when a user supplies a controlled cleaner observation. It does not measure physical camera retakes, changing viewpoints, time-varying instruments, or real-world inspection success. There is no real multi-capture dataset or real-gauge evaluation in this repository.
